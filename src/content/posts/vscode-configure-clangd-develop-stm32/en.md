## Introduction

Traditional STM32 development typically relies on IDEs like MDK-ARM or IAR. While capable, they lag behind modern editors in code intelligence, ergonomics, and extensibility. Combining VSCode with Clangd brings fast, accurate code analysis and completion to STM32 development, along with access to VSCode's rich ecosystem of extensions and AI coding assistants.

> [!NOTE]
> **Updated 2025-10-21**  
>  
> This article was originally written during `v1.0` of the [STM32 VS Code Extension](https://marketplace.visualstudio.com/items?itemName=STMicroelectronics.stm32-vscode-extension).  
>  
> As of `v3.6.4`, setup is much simpler: after installing the [STM32 VS Code Extension](https://marketplace.visualstudio.com/items?itemName=STMicroelectronics.stm32-vscode-extension), it automatically prompts you to install the required toolchain. Simply generate a `CMake` project from `STM32CubeMX` and open it—no manual toolchain wiring needed.  
>  
> You can largely skip the [Setup Steps](#setup-steps) section (though you still need [STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html) to generate projects), and jump straight to [Enhancements](#enhancements) for formatting, linting, and CMake tweaks.  
>  
> If you don't want the STM32 extension's bundled plugins cluttering your everyday VSCode setup, consider using VSCode [Profiles](https://code.visualstudio.com/docs/configure/profiles).

## Setup Steps

### 1. Install Base Tools

Download and install the required tools:
- [Visual Studio Code](https://code.visualstudio.com)
- [LLVM/Clang](https://github.com/llvm/llvm-project/releases) (provides the `clangd` language server)
- [STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html) (generates STM32 initialization code)
- [STM32CubeCLT](https://www.st.com/en/development-tools/stm32cubeclt.html) (provides `arm-none-eabi-gcc`, STM32 `SVD` files, `Ninja`, and `CMake`)

Make sure `LLVM`, `CMake`, `arm-none-eabi-gcc`, and `Ninja` are in your system `PATH`. Verify them in a terminal with `clangd --version`, `cmake --version`, `arm-none-eabi-gcc --version`, and `ninja --version`.

### 2. Install VSCode Extensions

> [!TIP]
> The Clangd extension conflicts with Microsoft's [C/C++](https://marketplace.visualstudio.com/items?itemName=ms-vscode.cpptools) extension—disable the C/C++ extension so Clangd can work properly.

Install these extensions from the VSCode Marketplace:
- [clangd](https://marketplace.visualstudio.com/items?itemName=llvm-vs-code-extensions.vscode-clangd) — C/C++ IntelliSense and diagnostics
- [STM32 VS Code Extension](https://marketplace.visualstudio.com/items?itemName=STMicroelectronics.stm32-vscode-extension) — STM32 build and debug integration

### 3. Configure the STM32 Toolchain Path

1. Press `Ctrl + Shift + P` in VSCode to open the Command Palette.
2. Run `STM32 VS Code Extension: Configure Cube CLT Path`.
3. Select your `STM32CubeCLT` installation directory (VSCode usually auto-detects it).

### 4. Generate and Import a Project

1. Create a new project in STM32CubeMX and choose **CMake** as the toolchain/project type when generating code.
2. Open the generated folder in VSCode.
3. Click the **STM32 VS Code Extension** icon in the Activity Bar and select **Import CMake Project**.
4. Select the root directory of the generated STM32CubeMX project.

### 5. Configure Clangd

1. Press `Ctrl + Shift + P` and run `Preferences: Open Workspace Settings (JSON)`.
2. Add the following to `settings.json`:

```json
{
    "clangd.arguments": [
        "--query-driver=C:/ST/STM32CubeCLT_1.17.0/GNU-tools-for-STM32/bin/arm-none-eabi-*", // Update to your arm-none-eabi-gcc path
        "--compile-commands-dir=${workspaceFolder}/build/Debug" // Update to your build directory
    ],
}
```

### 6. Finish Setup

1. Press `Ctrl + Shift + P` and run `Developer: Reload Window` or `clangd: Restart language server`.
2. Wait for Clangd to index the project.

Once complete, code completion and jump-to-definition should work cleanly with no false red squiggles, and you can press `F5` to debug directly over ST-Link.

### Enabling C++ Support

To use C++ in your project, update `CMakeLists.txt`:

```cmake
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS ON)

enable_language(C ASM CXX) # Replace the existing enable_language line
```

This enables C++ support and sets the standard to C++20.

### Generating HEX and BIN Files

To automatically generate `.hex` and `.bin` firmware images after each build, add the following to `CMakeLists.txt`:

```cmake
# Add custom command to generate binary and hex files
add_custom_command(TARGET ${CMAKE_PROJECT_NAME} POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O binary ${CMAKE_PROJECT_NAME}.elf ${CMAKE_PROJECT_NAME}.bin
    COMMAND ${CMAKE_OBJCOPY} -O ihex ${CMAKE_PROJECT_NAME}.elf ${CMAKE_PROJECT_NAME}.hex
)
```

### Adding Custom Source Files

To keep your own code organized in a dedicated directory (e.g., `Core/App`), add it in `CMakeLists.txt`:

```cmake
# Add sources path
file(GLOB_RECURSE SOURCES
    ${CMAKE_SOURCE_DIR}/Core/App/*.*
)

# Add sources to executable
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    # Add user sources here
    ${SOURCES}
)
```

### Adding Custom Include Paths

Similarly, register custom header directories:

```cmake
# Add include paths
target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    # Add user defined include paths
    ${CMAKE_SOURCE_DIR}/Core/App
)
```

### Tuning Compiler and Linker Flags

You can adjust flags in `gcc-arm-none-eabi.cmake` as needed:

```cmake
# Customize C++ flags (e.g. disable RTTI and exceptions)
set(CMAKE_CXX_FLAGS "${CMAKE_C_FLAGS} -fno-rtti -fno-exceptions -fno-threadsafe-statics")

set(CMAKE_C_LINK_FLAGS "${TARGET_FLAGS}")
set(CMAKE_C_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} -T \"${CMAKE_SOURCE_DIR}/STM32F411XX_FLASH.ld\"")
# Remove `--specs=nano.specs` if you need the full standard library
set(CMAKE_C_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} --specs=nano.specs")
set(CMAKE_C_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} -Wl,-Map=${CMAKE_PROJECT_NAME}.map -Wl,--gc-sections")
set(CMAKE_C_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} -Wl,--start-group -lc -lm -Wl,--end-group")
set(CMAKE_C_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} -Wl,--print-memory-usage")

# Enable float formatting in printf (unnecessary when using the full standard library)
set(CMAKE_C_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} -u _printf_float")
set(CMAKE_CXX_LINK_FLAGS "${CMAKE_C_LINK_FLAGS} -Wl,--start-group -lstdc++ -lsupc++ -Wl,--end-group")
```

## Troubleshooting

### IntelliSense Not Working

1. Confirm the Clangd extension is installed and Microsoft's C/C++ extension is disabled.
2. Make sure `compile_commands.json` has been generated in the build directory.
3. Verify the compiler path in `settings.json` (`--query-driver`).
4. Clangd may parse `.h` files as C headers even when they use C++ features—rename C++ headers to `.hpp` to avoid parse errors.
